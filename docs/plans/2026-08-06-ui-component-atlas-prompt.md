# UI 组件图集内置提示设计

## 目标

当工作台分类为 `ui` 时，在提交给生图模型的提示词末尾追加隐藏的强约束，使模型根据用户描述生成一张可拆分的 UI 组件图集，而不是游戏截图、场景画面或完整界面。

## 规则

- 用户提示词决定主题、题材、材质、配色和需要的组件类型。
- 默认使用简短、正向的英文视觉目标：干净的 2D 手游 RPG UI 精灵表、平滑纯色块、深蓝清晰描边、两档赛璐璐明暗、克制高光、统一线宽和易识别彩色图标。避免在主提示中罗列木纹、皮革、蚀刻等负面材质词，防止图像模型把否定项反向视觉化。
- UI 默认状态不发送“自由创作、自由风格、自然光照”等无意义控制词；用户明确选择的 UI 子类型、风格或光照仍会发送。
- 输出只包含独立 UI 组件，例如状态条、按钮、图标、摇杆、物品格、状态标记、面板边框等。
- 默认生成约 40 个组件，采用均衡 6 列图集和一致留白。
- 组件使用正视图、完整边界、统一风格和一致尺度，紧凑分行排列并保留清晰分隔，不重叠、不裁切。
- 组件集合应有层次，并至少覆盖头像、血条/能量条、按钮、通用图标、摇杆、物品格、技能图标、货币、设置、小地图、宝箱这 11 类，每类至少一组；同时可以按用户主题补充状态标记、钥匙、消耗品与面板边框，避免只生成少数大型组件。
- 禁止游戏场景、角色、环境、设备样机、完整界面、应用截图、说明文字、标签和水印。
- 所有按钮和面板保持无文字，不生成字母、数字或不可读的伪文字。
- 使用纯色、均匀中性背景；模型支持时优先透明背景，便于后续抠图拆分。
- UI 子类型只决定组件集合的用途，不允许把输出重新解释为完整界面。

## 实现与验证

在 `runtime/prompt.rs` 中增加按分类追加的 UI 图集指令，并放在参数优先规则之后以避免通用“禁止网格”规则与组件图集冲突。该段仅发送给模型，在历史提示词展示时隐藏。单元测试覆盖中文、英文、非 UI 分类和展示过滤。
