# 图片抠图工作区设计

## 目标

图片详情中的“抠图”不再执行客户端本地算法，而是进入独立的全屏抠图工作区。当前迭代只负责前端布局、类型选择、返回导航和后端能力占位，不新增或猜测服务端接口，不修改现有生成、上传和资产协议。

## 页面结构

- 顶部为返回按钮、页面标题和当前图片名称。
- 主体左侧为原图预览，始终使用图片详情当前选中的图片。
- 主体右侧为操作面板，提供固定类型：通用、人像、头像、皮肤、商品、服饰、天空。
- 类型使用稳定英文标识保存，界面根据语言显示中英文名称。
- 底部“开始抠图”只触发前端占位状态；服务端抠图能力接入前不生成本地结果。
- 返回时恢复原图片详情，保留当前图片和详情信息。

## 图片详情操作区

详情侧栏中的功能不更换内容，只调整布局。抠图、去黑、清晰放大放在第一张圆角功能卡中，采用两列紧凑按钮；重新编辑、再次生成放在底部独立圆角卡中，同样使用两列布局。每个按钮保留原点击行为、禁用状态和现有主题配色，并增加语义匹配的本地图标。

## 验证

- 契约测试确认抠图按钮进入工作区，不再调用本地抠图处理。
- 契约测试确认七种类型、原图预览、返回行为和后端占位文案存在。
- 契约测试确认详情功能卡为上三项、下两项的两列布局。
- 运行 `cargo check` 和完整 `cargo test`。
