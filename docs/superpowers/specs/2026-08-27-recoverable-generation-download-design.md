# 生图交付失败手动恢复设计

## 目标

当服务端生图任务已经成功、输出已写入 ArtForge 私有 OSS，但客户端下载到本地时超时或失败，失败缩略图提供独立的重新下载入口。重新下载不创建新生成任务、不重复扣除积分；本地文件完整保存并校验通过后，客户端发送现有交付确认，服务端删除对应 OSS 文件。

本设计只处理“ArtForge OSS → 客户端”的交付失败。Provider 返回图片 URL 后，服务端从 Provider 下载失败属于另一条服务端链路，不在本次范围内。

## 用户界面

### 普通生成失败

- 保持现有“生成失败”文案和“重试”按钮。
- “重试”继续创建新的生成任务，并遵循现有计费规则。
- 不显示重新下载图标。

### 已生成但下载失败

- 文案显示“图片已生成，下载失败”，避免误报为模型生成失败。
- 中间保留“重试”按钮，用于重新生成。
- 右上角常驻下载图标，用于恢复当前文件交付，不重新生成、不扣积分。
- 下载进行时禁用下载图标并显示加载状态，防止重复点击。
- 多图任务只在发生交付失败的卡片上显示下载入口。

### 成功与放弃

- 重新下载成功后，失败卡片原位替换为正常图片。
- 消息中心新增一次“图片下载完成”成功消息。
- 用户选择重新生成或删除失败卡片时，视为放弃该文件的手动恢复；客户端不伪造交付确认，未交付的 OSS 文件继续由现有 TTL 清理机制处理。

## 客户端数据模型

下载失败不再使用无上下文的通用失败结果，而是产生“交付下载失败”结果，并携带稳定关联信息：

- `client_request_id`
- `server_task_id`
- `item_index`
- `file_id`
- `sha256`
- `size_bytes`

现有 `PendingGenerationRecord` 继续作为权威恢复记录。`PendingDeliveryRecord` 增加向后兼容的失败卡片关联字段和放弃状态，保存上述交付信息、失败卡片 ID、本地路径和确认状态。恢复记录按用户 ID 与认证 epoch 隔离。

失败资产只增加运行时的“可恢复下载”状态；持久关联保存在恢复记录中，避免修改本地素材 SQLite 表结构。客户端加载本地数据时，以当前账号的恢复记录重新标记仍可恢复的失败卡片。签名下载 URL 不落盘。

## 下载与交付流程

1. 服务端终态任务的某个 item 为 `succeeded`，且包含 available 的 `TaskFile`。
2. 客户端自动下载失败时，为该 item 创建交付失败卡片，并把卡片与交付信息原子关联到恢复记录。
3. 用户点击下载图标后，客户端以卡片 ID 定位当前账号的恢复记录。
4. 客户端重新查询原任务，获取服务端新签发的短期 `download_url`，并按 `file_id` 与 `item_index` 核对结果。
5. 复用现有 5 分钟下载客户端，把文件流式写入受控 staging 目录。
6. 下载完成后校验字节数和 SHA-256，再原子保存到本地图库。
7. 持久化正常资产，原位移除失败卡片，并写入一次本地成功消息。
8. 调用现有 delivery ack 接口；服务端核对归属、摘要和大小后删除 OSS 对象，并把文件标记为已交付/删除。
9. ack 暂时失败时，本地资产保持成功可用，恢复记录继续保留并由现有恢复机制重试 ack。

自动恢复和手动点击使用相同的 `(client_request_id, file_id)` 互斥键，禁止并行下载同一个文件。客户端重启后，若 OSS 文件仍 available，自动恢复可继续；若尚未自动成功，失败卡片仍显示下载图标。

## 错误处理

- 再次超时、断网、HTTP 错误、大小不符、SHA-256 不符或图片无法解码：删除 staging 临时文件，不保存、不 ack，保留卡片和下载图标。
- 任务或文件属于其他账号：拒绝恢复，不发送下载或 ack 请求。
- 文件已过期、已删除或任务详情不再提供下载地址：清除可恢复关联，移除下载图标，提示“文件已过期，请重新生成”。
- 本地保存失败：保留恢复记录和下载入口，不 ack。
- 本地保存成功但 ack 失败：不回退本地资产，不再次显示下载失败；后台继续重试 OSS 清理。
- 并发点击或自动恢复已在运行：后续请求直接复用当前状态，不启动第二次下载。

## 服务端边界

本次不新增服务端接口和数据库字段。复用：

- 查询任务详情：每次为仍 available 且未过期的文件签发新的短期下载 URL。
- 交付确认：仅在客户端可靠保存并校验后调用；服务端删除 OSS 文件并记录交付状态。
- TTL 清理：处理用户主动放弃、长期未交付或已过期的 OSS 文件。

客户端不得保存或记录签名 URL，不得在本地保存前提前 ack，也不得直接持有 OSS 删除权限。

## 测试与验收

- 终态成功 item 下载超时时产生交付失败卡，而不是普通生成失败卡。
- 交付失败卡显示下载图标，普通生成失败卡不显示。
- 点击下载重新查询任务并使用新签名 URL，不创建新任务、不触发扣费。
- 文件经过大小和 SHA-256 校验且本地持久化后才发送 ack。
- 成功后失败卡片原位替换，只新增一次“图片下载完成”消息。
- 下载、校验或本地保存失败时不发送 ack，下载图标继续可用。
- ack 失败时本地图片保持可用，恢复记录可继续重试。
- 重启后恢复卡片关联；账号切换不会串用恢复记录。
- 多图任务按 item 独立恢复，无重复卡片、重复下载或重复消息。
- 文件过期后移除恢复入口，并给出重新生成提示。
